# Release Checklist — v0.11.0

RC: v0.11.0-rc.2 (2026-10-29), commit `aba6f0c`. Previous: v0.11.0-rc.1 (2026-10-29, `259c6de`), superseded before
any verification; rc.2 adds the 0.11.0 release notes (#226) and the `fast-uri` 3.1.9 override (#227). The release
commit also carries the `ajv` 6 and 8 overrides (#228, #229), which change development dependencies only.

Verified 2026-10-29 by three independent verifier agents, each building `v0.11.0-rc.2` in its own worktree, packing
the seven publishable packages and installing the tarballs with npm in fresh projects outside the repository (Node
24.21.0, macOS). Watch-mode claims were run at least five times each. No delivered plan carries a `Verified:` record;
these runs are the verification.

## Verification

- [x] addon-rebuild-gaps — type-only imports and `addAssetDependency` files rebuild the module in loader, CLI and
      Vite watch modes; `vite build --watch` reloads addons and config on change. Verified: loader `import type` edit
      5/5 (`declaration: true`), CLI `--watch` asset edit 6/6; Vite 6.4.5 and 7.3.7 dev server `import type` 5/5 and
      asset edit 5/5 each, `vite build --watch` addon, config, tsconfig and asset edits 5/5 each.
- [x] cli-error-exit-gaps — `-p <directory>` compiles its `tsconfig.json`; missing paths (TS5058/TS5057), invalid
      `tsconfig.json` options and a malformed `--configFile` are reported and exit 1. Verified, also once per build
      in watch mode (5/5). Not observed: diagnostics of a generator-added file in watch mode.
- [x] dependency-updates — `-core` hashes with `node:crypto` (no `create-hash`, `sha.js`, `cipher-base`);
      `lodash ^4.18.1`; runtime deps commander 15, comment-json 5, memfs 4.80, cjs-module-lexer 2.3, resolve.exports
      2.0.4. Verified from the packed tarballs and `npm ls`.
- [x] esm-check-precision — no 91001/91002 inside guarded UMD wrappers; 91021 ignores same-name locals; specifiers
      with query, fragment or percent-encoding resolve as at runtime. Verified with controls that still report. Not
      run: 91022–91024, `import()` in CommonJS, the `bundler` directory rule.
- [x] loader-asset-dep-and-cli-noemit — the loader rebuilds on every edit of an `addAssetDependency` file; `websmith`
      writes no JavaScript under `noEmit`. Verified: about 150 watch runs with first-edit delays of 0–3000 ms, some
      under CPU load, no stale rebuild (the CI flake of #228's run 40860284039 did not reproduce); `noEmit` and
      `--noEmit` write nothing with and without addons.
- [x] loader-options-once — the loader resolves options, config and addons once per compilation; watch mode and the
      persistent cache follow `tsconfig.json` (incl. `extends`) and `websmith.config.json`. Verified: one activation
      across 32 modules and watch edits; tsconfig and extended-file edits 6/6; filesystem cache invalidated. Found
      #230 (unknown loader `tsConfig` key gives a stack trace instead of a configuration error).
- [x] tsc-option-parity — profile `lib` names convert as in `tsconfig.json` (unknown names are errors); **breaking:**
      no forced `target: "ES5"` / `esModuleInterop: false`, `tsc` defaults apply (affects `node16`, `nodenext`,
      `preserve`). Verified: output identical to `tsc` (`diff -r`) for `node16`, `nodenext`, `preserve`, `commonjs`
      and `esnext` on TypeScript 5.7.3 and 6.0.3.
- [x] typescript-6-support — `typescript >=5.7 <7` across packages; **breaking:** `websmith-compiler` takes
      `typescript` as a peer instead of shipping 5.7.3. Verified: all seven tarballs declare the range; the CLI
      compiles with the project's 5.7.3 or 6.0.3; without TypeScript, and with 7.0.2, it exits 1 with the documented
      message.
- [x] vite-plugin — new `@quatico/websmith-vite` (Vite 6/7, 8 best-effort): addons in `vite build` and the dev server,
      per-environment profiles, errors through Vite, HMR reload. Verified on Vite 6.4.5 and 7.3.7 with TypeScript
      5.9.3 and 6.0.3; Vite 8.3.5 works with `--legacy-peer-deps`. Known issue #231: with an addon loaded, declaration
      emit errors do not fail `vite build`; shipped as a known issue in the release notes.
