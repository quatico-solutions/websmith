# Release Checklist — v0.10.0

RC: v0.10.0-rc.2 (2026-10-02), commit `761ee5c`. Previous: v0.10.0-rc.1 (2026-10-02, `41f02c9`); rc.2 adds #140,
#141 and #142 below. The items verified on rc.1 cover code rc.2 does not change, except the loader item, which the
qs-magellan run re-checked on rc.2.

Delivered since v0.9.0 (2026-03-16): `node-24-support`, `fix-ts-addons-esm-projects`, `esm-output-check`. The
release notes are `Release-Notes.md` `## [Unreleased]`, which becomes `## [0.10.0]` in the final release.

## Verification

- [x] node-24-support — websmith is built and tested on Node 24; published packages declare
      `engines.node: ">=22.12"`, Node 20 is no longer supported (**Breaking**). Verified 2026-10-02: all six packed
      packages declare it; no deprecation warnings on Node 24.21.0; Node 20 install warns `EBADENGINE`.
- [x] fix-ts-addons-esm-projects — TypeScript addons load in projects whose `package.json` declares
      `"type": "module"` (#111); the CLI writes compiled addons to `.websmith-cache/addons-cli` next to
      `tsconfig.json` instead of `lib/` next to the addons directory. Verified 2026-10-02 (no `lib/` created).
- [x] esm-output-check — the per-profile `esm` option (`runtime`, `check`, `ignore`) reports ESM problems in emitted
      JavaScript, including addon-generated code, with the source file, profile and addons in each diagnostic.
      Verified 2026-10-02: ESM91001/91010 with source, profile and addon; `warn` exits 0; `ignore` silences a file.
- [x] esm-output-check — `websmith` exits non-zero on error-level diagnostics it reports: syntax errors, and
      type errors where an addon needs type information (a plain build does not type-check) (**Breaking**).
      Verified 2026-10-02: syntax error exits 1, also with `--transpileOnly`; type error with a type-checked
      processor exits 1; a plain build with a type error exits 0 and prints nothing, as documented.
- [x] esm-output-check — the webpack loader fails the build for syntax, declaration-emit and configuration errors
      and ESM check findings, not type errors (**Breaking**). Verified 2026-10-02 with webpack 5.111.1 and
      webpack-cli 6.0.1: each fails with exit 1, the config error once; a pure type error compiles.
- [x] Smoke test in a `"type": "module"` project on Node 24: CLI build with a profile using `esm`, and a webpack
      build through `websmith-loader`. Verified 2026-10-02: both builds exit 0 and their output runs on Node 24.
- [x] rc.2 #141 — the loader's addon compilation no longer warns `Cannot find module` for Node built-ins such as
      `path` or `node:fs/promises`; unresolved packages still warn. Verified 2026-10-02 in qs-magellan on Node 24:
      18 warnings with rc.1, 0 with rc.2; unit tests cover the built-in and missing-package cases.
- [x] rc.2 #142 — `ErrorTrackingReporter` is exported from `@quatico/websmith-core`. Verified 2026-10-02: in a
      qs-magellan copy, wrapping `magellan compile`'s reporter makes a syntax error exit 1 and a clean project exit 0.
- [x] rc.2 #140 — the READMEs match the behaviour (no automatic `websmith.config.json` lookup, no default addons
      directory, absolute emitted paths, the `websmith` bin, all loader options) and the CLI no longer prints
      `command duration`. Verified 2026-10-02 by a review that ran each behavioural claim against the built CLI.
- [x] Downstream: qs-magellan (`864eae0`) on rc.2, Node 24.21.0: build, lint, typecheck, 733 unit tests and 90 e2e
      tests pass, the loader template's production bundle is byte-identical to the 0.9.0 baseline. Magellan has to
      move to Node >= 22.12 and widen its `0.9.x` peer ranges to adopt 0.10.0.
