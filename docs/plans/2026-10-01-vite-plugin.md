## Changelog

- New package `@quatico/websmith-vite`: a Vite plugin that compiles `.ts`, `.tsx`, `.mts` and `.cts` modules with
  websmith, so generators, processors, transformers and result processors run in `vite build` and in the Vite dev
  server. It takes the webpack loader's options (`configFile`, `profile`, `transpileOnly`), reports TypeScript, ESM
  check and configuration errors through Vite, fails `vite build` on errors, and updates dependent modules on HMR.

## Motivation

Issue #60 asks for websmith in Vite projects. Today websmith runs as a `tsc` drop-in CLI and as a webpack loader;
projects that build with Vite cannot use their addons (e.g. Magellan's client/server function transforms) without
a separate `websmith` step before Vite. A Vite plugin puts the addon pipeline where those projects already compile,
with Vite's dev server and HMR.

A first attempt exists on `feature/60--plugin-for-vite` (2025-07, `packages/vite-plugin`), with a skeleton on
`vite` (2025-03). It predates profiles, the Node 22.12 baseline and the ESM check, imports
`@quatico/websmith-core` types from the webpack loader, logs with `console`, and on any error returns the source
unchanged, which would let a broken build pass. This plan writes the package fresh off `develop` and reuses the
attempt's ideas and tests where they still fit.

## Design

### Approach

- **Package:** `packages/vite`, published as `@quatico/websmith-vite`, default export `websmith(options)` returning
  a Vite `Plugin`. Peer dependency on `vite`. MIT headers, `AGENTS.md` rules (no `console`, report through the
  reporter).
- **Options:** the webpack loader's: `configFile` (default `./websmith.config.json`), `profile`, `transpileOnly`,
  `addonsDir`, `addons`, plus Vite's `include`/`exclude` filter (default `/\.(c|m)?tsx?$/`, `node_modules`
  excluded).
- **Pipeline position:** `enforce: "pre"`, so websmith sees TypeScript before Vite's esbuild strips types. The
  plugin returns JavaScript and a source map; esbuild then has nothing left to transform for that module.
- **Per-module compile:** the same per-file path the webpack loader uses (`TsCompiler.build(resourcePath)`): one
  compiler instance per resolved options, the selected profile and its `depends`, generators and result processors
  once per build.
- **Diagnostics and failure:** errors through `this.error` (fails `vite build`, shows the overlay in dev), warnings
  through `this.warn`; configuration errors of the selected profile once per build; the ESM check reports per
  module like the loader. Nothing is printed with `console`; nothing is swallowed.
- **Dev server and HMR:** `addWatchFile` for every file a rule or addon reads, `websmith.config.json` included;
  `handleHotUpdate` invalidates modules that depend on a changed file; a changed config file re-resolves options.
- **Files addons write:** generators and result processors keep writing to the file system as with the loader;
  `vite build` additionally registers emitted JavaScript with `emitFile` only where the plan's Open Points decide
  so.
- **Tests:** unit tests in the package; e2e in a new `packages/vite-test` mirroring `webpack-test` (build, dev
  server via `createServer`, HMR edit, broken profile, ESM finding).

### Open Points

- [ ] **The seam.** `TsCompiler` lives in `packages/webpack` and carries webpack types (`WebpackLoaderOptions`,
      `WebpackAddonService`). Either the Vite plugin depends on `@quatico/websmith-loader`, or a bundler-neutral
      per-module compiler moves to `@quatico/websmith-core` first and both hosts use it. The tracer decides, by
      building the thinnest path both ways far enough to compare.
- [ ] **Supported Vite majors** and whether e2e runs a matrix.
- [ ] **`vite dev` with type information:** the dev server compiles one module per request; addons that need a
      Program (type-info addons) may be too slow per request. Measure in the dev-server slice; fall back to
      `transpileOnly` in dev if needed, documented.
- [ ] **Files generated by addons in `vite build`:** written to disk only, or also `emitFile`d into the bundle
      output.
- [ ] **SSR builds** (`ssr: true`) and how a profile maps to client vs. server environments (Vite 6 Environment
      API).

- `feature/vite-plugin-diagnostics` — TypeScript, ESM check and configuration errors through `this.error`/`this.warn`, configuration errors once per build, `vite build` fails on errors, no `console` <!-- builds: Vite diagnostic reporting for websmith -->
